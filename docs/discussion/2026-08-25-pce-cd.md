# PC Engine CD: the System Card, and who is supposed to know about it

The last piece of PC Engine CD. Everything else was already settled - the Disk
Control Interface is unnecessary (502 Redump entries, zero multi-disc titles),
and Beetle PCE Fast covers HuCard and CD from one binary.

## What the core actually does

Measured on the Brick, Beetle PCE Fast v1.31.0.0, *Ys Book I & II (USA).chd*:

| Case | Result |
|---|---|
| CD, System Card present | **59.81 fps against 59.8200, 0 resyncs**, 256x243, CHD read natively |
| CD, System Card absent | `retro_load_game` returns **false** |
| HuCard, System Card absent | runs normally |

**CHD needs nothing.** `chd_load` is compiled in and the card reads at
`hunkbytes=19584` without any work on our side. That was the one thing that
might have been a real project and is not. CUE/BIN is untested - there is no
such content to hand, and it is worth saying so rather than assuming it follows.

The core names the file in its log - `MDFN_MakeFName: <dir>/syscard3.pce` -
immediately before failing. That is the only signal available and it is not part
of any contract.

Its BIOS choice is a **core option**, `pce_fast_cdbios`, offering System Card 1,
2 and 3, their US variants, and Games Express. Diatom already reaches that
through `SETOPT` and `--core-option`, so nothing was needed there.

## The awkward fact

The third row of that table is the whole problem. **The same binary needs a
System Card for a `.chd` and needs nothing for a `.pce`**, so the requirement is
per-content, not per-core. A frontend-side table keyed on the core - which is
what RetroArch keeps - would be wrong by construction here: it would demand a
System Card for HuCard games that do not need one.

And `retro_load_game` returning false is the same answer the core gives for a
corrupt ROM. libretro has no firmware query. That is a genuine gap in the API,
not something being overlooked.

Which matters more than a nicer message, because of ADR-0009's rule:

> `ERROR` means the game never started. `EXIT` means it ran and stopped.

A missing System Card means the game never started, so the launcher keeps the
display and must hear `ERROR`. Calling it `rom_unreadable` sends the player
hunting for a bad download when the fix is a file they can supply.

## What was chosen

The launcher says. `RUN core= rom= firmware=syscard3.pce`, or `--firmware`
standalone, and Diatom checks the file is readable in the system directory
before asking the core for anything. Reasoning and the three rejected
alternatives are in
[ADR-0017](../decisions/0017-firmware-is-declared-not-known.md).

Driven over the socket on device:

| | Result |
|---|---|
| firmware declared, present | `RUNNING` at 26.8 ms, then 59.81 fps |
| firmware declared, missing | `ERROR code=bios_missing msg=syscard3.pce` at **0.01 s** |
| firmware not declared, missing | `ERROR code=rom_unreadable` - the old behavior, unchanged |
| HuCard, nothing declared | runs |

The third row is the point of the design as much as the second. A launcher that
knows nothing about `firmware=` behaves exactly as it did, because ADR-0009
specified that unknown keys are ignored. The 0.01 s in row two is because the
core is never loaded at all.

## The limit, stated plainly

**The check proves presence, not validity.** A 2 KB file of random bytes named
`syscard3.pce` was accepted and the game reported `RUNNING`. The real card is
262,144 bytes. Beetle PCE Fast does not validate it, and neither does Diatom -
validating means knowing what the file should be, which is the core-list
argument again. The launcher already names the file, so it is better placed to
hash it.

So a wrong System Card produces a game that starts and misbehaves, and nothing
in this stack will say so. That is a real hole; it is just not one Diatom should
be the component to fill.

## Found on the way

The ADR index in `decisions/README.md` **stopped at 0012** - 0013 through 0016
were written and never listed. The same drift as the register, in a second file,
for the same reason: adding the ADR is the work and adding the row is the
bookkeeping. `make check` now fails on an ADR missing from the index, which cost
four lines.
